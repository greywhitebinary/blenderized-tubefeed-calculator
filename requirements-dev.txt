# pyarrow - DELIBERATELY dev-only, not in requirements.txt. Reasoning:
# src/data_loader.py prefers a pre-built Parquet cache under data/processed/
# and falls back to CSV, but data/processed/ is gitignored (see .gitignore
# and CONTEXT.md §4) and contains no tracked files - a fresh clone (which is
# exactly what Streamlit Community Cloud deploys from) never has the cache,
# so the deployed app has always taken the CSV fallback and never actually
# imports pyarrow at runtime. pyarrow is needed only for the local dev
# workflow of running src/build_parquet.py to build/read that cache for
# faster local iteration (~20x per CONTEXT.md §3) - a dev convenience, not
# something Cloud's production runtime touches today. If the Parquet cache
# is ever committed/shipped to change that, pyarrow must move back to
# requirements.txt as a deliberate, documented decision - not silently.
# UPPER BOUND IS LOAD-BEARING. pyarrow 25.0.0 SEGFAULTS (exit 139, no
# traceback) inside libarrow's PoolBuffer::Reserve when Streamlit
# converts a DataFrame to Arrow for display. It took CI down on
# 2026-07-31: three AppTest checks died with no error message, while the
# same commits passed locally purely because this laptop still had 24.0.0
# and this line let a fresh machine resolve 25.
#
# Note the deployed app is NOT affected -- pyarrow is deliberately absent
# from requirements.txt, so Streamlit Cloud never takes that code path.
# This was a CI-only crash in a package production doesn't install.
#
# Before raising the bound: run the AppTest checks in a FRESH venv, not
# this one. `pytest` alone will not catch it -- the crash is in
# Streamlit's DataFrame rendering, which only the AppTests exercise.
